## Purpose

让用户无须打开命令行即可把 DSH checkout 升级到最新:检查远端更新、以受控的五步流程完成拉取、安装、构建与重启,并在任何一步失败时保留可诊断、可重试的状态。

## ADDED Requirements

### Requirement: 检查更新

系统 SHALL 在启动器启动时静默执行 `git fetch origin`,并与 `origin/<当前分支>` 比较;概览页显示当前 HEAD、是否落后及落后提交数。检查失败(离线、仓库异常)SHALL 不阻塞启动器,更新卡显示不可用状态。

#### Scenario: 自动检查发现更新
- **WHEN** 启动器启动且本地落后于远端
- **THEN** 更新卡高亮显示"更新可用"及落后提交数,不自动升级

#### Scenario: 检查失败
- **WHEN** `git fetch` 失败(如无网络)
- **THEN** 更新卡显示不可用,升级入口不可用但不影响服务使用

### Requirement: 一键升级

系统 SHALL 提供升级入口,用户确认后按 预检 → 拉取 → 安装 → 构建 → 重启 五步顺序执行;每步有独立状态(待执行/进行中/完成/失败),实时输出进入升级进度视图。

#### Scenario: 完整升级成功
- **WHEN** 用户确认升级且远端有新提交
- **THEN** 五步依次成功,结束后展示 旧 HEAD → 新 HEAD,自动重启服务(开发模式开启时同时重启 `dev:web`)并重新打开界面

#### Scenario: 升级期间禁止启动服务
- **WHEN** 升级流程进行中
- **THEN** 服务启动/停止/重启操作被禁止,托盘与概览页按钮不可用

### Requirement: 升级预检

系统 SHALL 在拉取前检查 DSH checkout 的已跟踪文件树:存在未提交改动时 SHALL 阻止升级并说明,未跟踪文件不阻止。升级前的服务停止 SHALL 在预检通过后执行。

#### Scenario: 脏树阻止升级
- **WHEN** checkout 存在已跟踪文件的未提交改动
- **THEN** 升级停留在预检步并明确指出冲突文件,不拉取任何内容

#### Scenario: 未跟踪文件不阻止
- **WHEN** checkout 仅存在未跟踪文件(如本地配置、构建产物)
- **THEN** 预检通过,升级继续

### Requirement: 升级失败恢复

系统 SHALL 在任一步失败时停止流转、停留在失败步骤,保留该步完整输出,并提供"重试"选项从失败步骤继续;已成功的步骤不重跑。

#### Scenario: 拉取失败重试
- **WHEN** `git pull --ff-only` 失败且用户点击重试
- **THEN** 从拉取步重新执行,预检与已停止的服务保持不动

#### Scenario: 构建失败
- **WHEN** 构建步(`pnpm run clean && pnpm run build`)以非零码退出
- **THEN** 升级停在构建步,展示构建错误输出,服务保持停止,可重启原有服务继续使用

### Requirement: 升级边界行为

系统 SHALL 在升级期间保持服务停止;升级完成或用户中止后,服务状态恢复为停止(不自动重启,除非升级成功)。用户中止升级 SHALL 杀死当前正在执行的步骤进程并置为失败态。

#### Scenario: 升级后服务已停止
- **WHEN** 升级成功完成
- **THEN** 服务自动重启并打开界面

#### Scenario: 中止升级
- **WHEN** 用户在升级进行中点击"取消"
- **THEN** 当前步骤进程被终止,状态置为失败,服务保持停止,可手动重新启动
